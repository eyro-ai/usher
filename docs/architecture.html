Because the index is derived, a rebuild regenerates it from whatever is actually in the folder. Files that vanished stop appearing; moves and renames need no handling at all, since identity lives in file metadata rather than in a path. Deleting the whole index and rebuilding is routine, not recovery.

Rules

The four that earn their place

Each is cheap, and each prevents a failure that is invisible from the reader's side.

Evidence must be verbatim

Every claim carries a span copied exactly from the source, checked by substring containment. A claim that fails is discarded, never repaired. This is what makes an answer checkable rather than merely trusted, and it costs one string comparison.

The skip log cannot describe what it skipped

Excluded material is logged as a rule id and a count — skipped 3 item(s) (rule: no_one_to_ones). A descriptive log recreates the excluded content somewhere else, which is the leak the exclusion existed to prevent. The trap is that a helpful log is the obvious thing to write.

Mutable records are refetched, never read from the sheet

Linear issues and open PRs supply identity and a link, nothing more. If the source is unreachable, the answer says so — a quiet fallback to a cached row is unfalsifiable from the reader's side, which is what makes it corrosive.

Names resolve to ids before filtering

Participants are stored as ids, so matching a raw name returns zero rows — silently, and indistinguishably from genuine absence. Nobody investigates an empty result, which makes this the most deceptive bug available here.

And one thing never done

Counts from the KB are never presented as measurements. "Three people raised churn" is false; the truth is that churn appears in three recordings that happened to be captured and ingested. The corpus is a convenience sample that merely looks tabular.

Log

Decisions, including the ones reversed

D1

Standalone KB. Own schema, own skills.

D2

Purpose is recall, not automation. "What was said about X" — explicitly not traceability, ticket creation, or status reporting. D12 exists because the design had drifted away from this.

D3

Three sources. Recordings are the corpus; Linear and GitHub are context. Adapter-shaped, so any subset can run.

D4

Storage: Notion. Superseded by D8 — pages could not be deleted, making a mis-filed write permanent, and relations could not carry properties.

D5

Tier partitioning with default deny. Superseded by D12. Built on a requirement — who else reads this — that was never confirmed.

D6

Generic, not organisation-specific. No teams, repos, or ids in the skills; everything deployment-specific lives in one config file.

D7

Skills plus a config file as the user-facing surface. Amended by D11.

D8

Storage: Google Drive. Originally chosen for its ACLs; after D12 it is simply a good place — deletion works, Docs are full-text indexed, and people can browse it.

D9

Folders organize; indexes are derived and rebuildable. Survives D12 intact, and is the reason hand-reorganisation costs nothing.

D10

Permission classes discovered from ACLs. Superseded by D12 along with the rest of the access model.

D11

Tested rule library; Drive via the Google API. The rules that decide whether the system fabricates are code with tests, not prose in a skill.

D12

Cut back to the stated purpose. One folder, no access model, no edge table. Seven decisions had chained off a single unconfirmed premise, and cross-source linking was never asked for — it was the option D2 rejected.

Risk

Not yet verified

The Plaud connector is unauthorized, so its tool surface is assumed: a stable id, a timestamp, and full transcript text.

  • Summaries only — verbatim evidence becomes impossible and claims stop being checkable. Enough to reopen the data model rather than patch around.
  • No speaker segmentation — attribution stays mostly empty.
  • No folders or tags — harmless now that everything lands in one folder.

Phase 2 must also confirm that appProperties survives a move and a rename. If it does not, identity needs a different mechanism before more code is written.
