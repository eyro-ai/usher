Architecture · rev C · 2026-08-12

Recordings KB

A searchable memory of voice recordings, with issue tracking and code review as supporting context. Built so that what it tells you is checkable, and what it hides stays hidden.

Plaud · Linear · GitHub Drive folders + folder ACLs 3 Claude skills + config Design complete 2 connectors unauthorized
Problem

Three sources, one of which has no permission model

Voice recordings hold the reasoning behind decisions; issue trackers and pull requests hold the work that followed. Neither is searchable from the other, and recall degrades to whoever remembers the conversation.

The hard constraint is access. Linear and GitHub carry real ACLs that can be mirrored. A pocket recorder does not. A recording belongs to whoever was carrying the device, captures people who never opted in, and has no org permission model to inherit — so every recording needs a sensitivity label assigned rather than derived. That single asymmetry shapes most of what follows.

Shape

Pipeline and tiers

Tiers are Drive folders, not rows with a permission column. People reorganize documents inside them by hand; indexes are rebuilt from what is found. Retrieval attempts each folder; Drive denies what it will.

§1

Data model

tabs

The folder tree is the schema. A tier is a Drive folder whose sharing settings are its ACL; the index lives inside that folder and inherits them. Below records/, people arrange documents however they like — subfolder structure carries no meaning to the system, which reads only the boundary. Indexes are caches, rebuilt from whatever is actually on disk.

TabRow isKeyCarries
RecordsOne source event{source}:{source_id} Title, occurred_at, participants, tier, raw_doc_id, mutable, content_hash
ClaimsOne distilled statement{record_id}#{n} Statement, type, speaker, confidence, verbatim evidence, anchor
LinksOne cross-source edgelink_id From, to, basis, confidence
EntitiesOne person or projectentity_id Aliases: recorder label ↔ Linear user ↔ GitHub handle

Atomic unit

One row per recording, per issue, per pull request — never per commit. Mixed granularity is what quietly destroys ranking: long documents match everything, so relevance stops meaning anything.

Copy the immutable, link the mutable

ContentImmutableTreatment
Recording + transcriptyesFull copy into a Doc. This is the corpus.
Merged pull requestyesSnapshot Doc as at merge.
Open pull requestnoRow + link. mutable = TRUE
Linear issue / projectnoRow + link. Status always refetched.

There is deliberately no status column anywhere. Caching issue state is the single change that would make the KB start lying, and a reader cannot tell a stale cell from a fresh one.

Two layers, never merged

Raw text is preserved untouched; distillation writes to separate rows. Retrieval hits the distilled layer, because transcripts are long, full of filler and recognition errors, and match almost any query. Keeping raw intact means distillation can be re-run whenever prompts improve.

Edge provenance is a column, not a vibe

Every cross-source edge records how it was derived, and the three are never presented as equivalent:

  • explicit-id A ticket ID in a branch, PR title, or commit. A fact. Traversed freely.
  • time-proximity Co-occurrence in time. A candidate, not a finding.
  • llm-inferred A model's guess. Traversed only on explicitly exploratory questions, with the whole branch marked.

An edge is materialized only in the class that can see both of its endpoints — the intersection of their audiences. If that intersection is empty, the edge exists nowhere. Restrictiveness is a partial order once classes are discovered rather than ranked: two teams are incomparable, neither stricter, so "store it at the more restricted end" has no meaning.

Without this, inferred links harden into false history over months and nothing distinguishes them afterwards.

Drift — what a rebuild cannot fix

Most integrity errors vanish once the index is derived: a rebuild regenerates it from what is on disk, and vanished files simply stop appearing. What remains is the trap in Drive's permission model — folder ACLs are inherited, but shares granted directly on a file survive a move. A document dragged from Open into Personal can stay readable by whoever held a direct share. Reconcile checks each file's effective permissions; folder inheritance is not proof of access.

§2

Access model

tiers

The governing rule: an artifact inherits the maximum sensitivity of everything it was derived from — summaries, rollups, the entity graph, and titles alike. Existence is information; a title can leak what a locked body protects.

Owner-only folderThe default landing zone. No ladder needed to define it — shared with nobody is the bottom of any permission lattice.
…every distinct ACL found in the treeEach becomes a class, discovered by scan. Two teams with separately-shared folders become two classes without anyone naming them.
Workspace-shared folderSimply the widest class that happens to exist.
Excluded — never ingested1:1s, HR, compensation, legal, health. Not a tier: this content never enters the system at all.

Classes are discovered, not declared

There is no configured personal/group/open ladder. The system computes each folder's effective ACL and groups folders sharing one audience into a class. The grouping cannot be dropped entirely, because of one constraint:

A derived artifact can only be shared with the intersection of its inputs' audiences. Raw documents are fine at any granularity — Drive enforces each one. An index is not: it is a single file with a single ACL, so every row is visible to anyone who can open it. Hence one index per distinct audience. That is what a tier always was; the error was declaring it rather than discovering it.

The folder is the boundary

Enforcement is Drive's own folder ACL, not a query-time filter. A filter needs a trusted enforcement point and a permission table that drifts; worse, a filter applied by an agent is a filter an agent can be argued out of. Because the file is Drive's permission unit, one sheet cannot hold rows of differing sensitivity — so each tier folder carries its own index, and the layout enforces what would otherwise be a rule someone has to remember.

The folder is also the only authority on class. Nothing stores a label to be compared against reality; membership is computed from the ACL on every rebuild, so the two cannot disagree.

The price is that share changes re-partition the derived layer with no file move to detect. Editing a folder's sharing invalidates indexes while the tree looks identical, so reconcile scans effective ACLs every run rather than only walking files.

The cost is bluntness: some material sits in a tier more restrictive than strictly necessary. That is the correct direction to fail — someone has to ask, rather than someone seeing what they shouldn't.

Three leaks that look like features

Descriptive skip logs. Recording why an excluded item was skipped reconstructs it in a file with different permissions. Log the rule and a count, never the title.

Suppressed-result counts. “3 further results exist in tiers you cannot access” is an existence leak. Out-of-scope material is absent, not redacted.

Saving a good answer back. A cross-tier synthesis written into a lower tier moves restricted content across the boundary. Answering across tiers you hold is fine; persisting it downward is not.

Agent identity closes the loop: the agent always acts with the asking human's own credentials. A service token holding everyone's access, answering for individuals, turns the KB into a privilege-escalation device.

§3

Ingest

flow

Watermark-driven and incremental. A full rescan exists only as an explicit rebuild when the extractor version changes.

StepRuleWhy
1 · excludeEvaluate never-ingest patterns before content is fetchedExcluded material never enters the agent's context at all
2 · tierUnresolved ⇒ Personal, alwaysOver-restriction costs a question; under-restriction costs an incident
3 · writeRaw Doc written directly into the target tierWrite-then-move leaves content at the wrong ACL for a window
4 · distillEvidence must appear verbatim; failures discarded, not repairedSubstring containment is a decisive, judgement-free fabrication check
5 · linkEdge stored only where both endpoints are visibleOtherwise the edge table leaks the existence of records you cannot open
6 · commitWatermark advances only after the record fully landsA crash mid-record retries; it does not silently skip

Distillation is contracted to 3–15 claims per record — an extractor emitting forty dilutes retrieval until ranking is meaningless. Re-extraction replaces all claims wholesale rather than merging, because merged versions produce near-duplicates that never converge.

Deduplication keys on the stable source ID, never the title: recording titles are not unique, and titles are the thing most likely to change upstream. Identity is stamped into hidden Drive file metadata, so it survives the renaming and reorganising people do by hand — paths and filenames are never used to identify a document.

Rebuild is the normal path

Indexes are caches, and regenerating one is routine rather than recovery. A rebuild walks the tier folder, reads each file's identity stamp, refetches the link-only records, and rewrites the index from what is actually there. Files that vanished stop appearing; files that arrived appear. Moves need no special handling, because nothing tracked where a document used to be.

Distillation is the only expensive step, so claims are cached by content hash and scoped per tier. Content addressing makes the cache immune to reorganisation within a tier — a rebuild after a reshuffle costs almost nothing. A document moved between tiers misses the cache and re-distills, which is the correct security behaviour: claims must never pre-exist in a tier before the document arrives.

§4

Retrieval

funnel

Scope is discovered, not configured. The skill holds no table of who may read what — it attempts each tier store and lets Drive deny. Consequence: the same question yields different answers for different people. Correct, but it makes the scope note mandatory, since an unscoped partial answer reads exactly like a complete one.

StageMechanismHandles
1 metadataSheet columns: date, participants, source, topic, typeMost questions are scoped. Exact and free.
2 lexicalClaim text + Drive full-text over raw DocsNames, ticket IDs, error strings — what semantic search is worst at
3 semanticAgent reranks the candidate setConceptual recall only

No embedding store. At this corpus size, full-text plus distilled statements plus agent reranking beats a vector index that must resync on every re-extraction. The sync burden lands immediately; the recall benefit lands much later, if ever.

Anything marked mutable is refetched live before it enters an answer. If the source is unreachable the answer says so — a quiet fallback to a cached row is unfalsifiable from the reader's side.

What every answer carries

Supporting claims with source links and dates; provenance for anything reached through an inferred edge; which tiers were searched; “as of” stamps on live data; and an explicit not found rather than plausible filler. What was said, what was inferred, and what is live stay visually distinct.

Two failure modes worth naming

Unresolved aliases return silence. Participants are stored as IDs, so matching a raw name returns zero — indistinguishable from genuine absence. Names resolve to entity IDs before filtering, never after.

Counts are not measurements. “Three people raised churn” is false; the truth is that churn appears in three recordings that happened to be captured, ingested, and are readable by you. The corpus is a convenience sample that merely looks tabular.

§5

Tier changes

by hand

A tier change is a person dragging a document between folders in Drive. There is no tool-mediated move, and the tooling cannot require one.

The trade this makes

Safety checks become detective rather than preventive. Participant exposure and exclusion rules can no longer block a move — they run at the next reconcile and report. The interval between a careless drag and that reconcile is genuine exposure, and no tooling closes it while hand-moves remain the interface. A promote helper runs the checks first for those who want them, but it is a convenience, not a gate.

Reconcile therefore checks, after the fact: exclusion rules re-evaluated against the new tier, participant exposure flagged for a human, effective file permissions compared against the folder, and edges re-materialized at the intersection of their endpoints' audiences.

Demotion is containment, not erasure

Moving a document somewhere more restrictive does not undo exposure. Whoever read it, read it; Drive keeps revision history; copies others made are untouched. Shares granted directly on the file while it sat in the open persist through the move and must be revoked explicitly — which is precisely why effective permissions are checked rather than assumed.

Claims follow their document for free

Because claims are regenerated at the document's current location, a hand-move needs no bookkeeping: the old tier's rebuild stops emitting them, the new tier's produces them. Nothing is migrated, nothing is orphaned in a sheet the person never knew existed. This is the main dividend of making indexes disposable — the failure where a moved file leaves stale derived rows behind cannot arise.

Decisions

What was decided, and what it cost

D1

Standalone, not an extension of an existing KB

whyA different corpus and a different access problem than a meeting-notes graph fed by scheduled calls.

D2

Purpose is recall, not automation

whyOptimizing for “what was said about X” rather than ticket creation or status reporting.

costEffort goes to ingest quality and retrieval; no write-back into Linear or GitHub.

D3

Three sources, adapter-shaped

whyRecordings are the corpus; issues and pull requests are context. Any subset can be enabled; only the recorder is required.

D4

Storage: Notion

superseded by D8Retained for the trail. Two properties killed it: pages could be created and moved but never deleted, making a mis-tiered write permanent under a default-deny policy; and relations could not carry properties, forcing edge provenance into a workaround.

D5

Tier partitioning with default deny

whyThe recorder has no source ACL to mirror, so labels must be assigned regardless. Partitioning enforces by possession, which survives a dumb store and an argumentative agent.

costCoarser than per-document permissions; cross-tier synthesis needs both tiers held.

D6

Generic, not organisation-specific

whyNo teams, repos, folder names, or store IDs in the skills. Everything deployment-specific lives in one config file.

effectSolo versus team stops being a design choice and becomes configuration — a single-user deployment simply has one tier.

D7

Packaging: three skills plus a config file

whyIngest, search, promote. No build step and no service; the agent drives the connectors directly.

costWeakest at bulk and scheduled sync — mitigated by a scheduled routine if it bites.

D8

Storage: Google Drive, company workspace

whyDeletion actually works, which de-risks default deny. Folder sharing maps onto tiers directly (refined by D9), so a tier change is an ordinary file move: visible, auditable, and reversible. Edge provenance becomes an ordinary column. Full-text indexing of Docs supplies the lexical layer at no cost.

costNo database primitives — no typed properties, relations, or views. Referential integrity is ours to keep. The file is the permission unit, so the index must shard per tier.

D9

Folders organize; indexes are derived and disposable

ruleData lives in folders. People move original documents by hand, freely. Every index rebuilds automatically. Access is the Drive folder's own ACL.

gainThe folder becomes the single authority on tier — a label cannot disagree with reality because it is read from reality. Hand-moves need no bookkeeping, and rebuild-from-scratch removes a whole class of integrity bugs.

costPromotion checks become detective rather than preventive. Drive's direct-share behaviour survives moves, so effective permissions must be verified rather than inferred from the folder. Moving between classes re-runs distillation.

D10

Permission classes discovered from ACLs, replacing the declared ladder

whyA derived artifact can only be shared with the intersection of its inputs' audiences, so one index per distinct audience is unavoidable — but that grouping can be discovered from effective ACLs instead of declared as a fixed ladder.

gainArbitrary fine-grained sharing works; configuration loses the whole tiers block, leaving only roots and a default landing folder.

costIndex count scales with distinct ACLs, so ad-hoc per-file sharing multiplies classes. Restrictiveness becomes a partial order, changing the edge rule to an intersection. Share changes re-partition the derived layer with no file move to detect, so reconcile must scan ACLs every run.

Risk

Assumptions not yet verified

The recorder's connector is unauthorized, so its tool surface is assumed rather than known. The design assumes it returns a stable ID, timestamp, and full transcript text.

  • Summaries only, no transcript — verbatim evidence becomes impossible and claims stop being checkable. Material enough to reopen the data model, not patch around.
  • No speaker segmentation — attribution stays mostly empty, weakening the identity join across sources.
  • No folders or tags — nothing derives tier, so every recording is labelled by hand and promotion becomes the primary interaction rather than an occasional one.

These are assumptions, recorded as such. Verify before building.
